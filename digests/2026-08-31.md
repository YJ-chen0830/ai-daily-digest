## 📌 頭版焦點

### [tt-a1i/archify](https://github.com/tt-a1i/archify)

Archify 是一套針對 AI coding agent（Cursor、Claude Code、Codex CLI、OpenCode）設計的架構圖渲染與驗證系統。工作流程相當明確：agent 輸出 typed JSON IR，Archify 確定性地將其編譯成含動畫的自包含 HTML/SVG，支援五種圖表類型（架構、工作流、序列、資料流、生命週期），並可匯出 PNG、SVG、WebM 及社群分享卡。

更值得關注的是「Before / Delta / After 比較」功能——能在 merge 前審查兩份已驗證的架構快照，精確標示新增、移除、變更、移動的節點與連線。這解決了一個真實痛點：架構文件往往在程式碼上了版控後才更新，而 Archify 試圖讓圖表與程式碼的演進同步成為 review 流程的一部分。

今日單日 +3,722 顆星，總星數已近 3.6 萬，且版本號已到 v2.16.0，4 月上線以來迭代明顯活躍，並非一夕爆紅的空殼專案。對生態系的潛在影響是：若「diagram as code + agent skill」這個組合站穩，Mermaid 等傳統文字圖表方案的定位將受到擠壓。

### [THU-MAIC/OpenMAIC](https://github.com/THU-MAIC/OpenMAIC)　⭐ 24,930（今日 +1,370）
- **一句話定位**：清華大學出品的多 agent 互動式教學教室，一鍵部署，支援 Vercel。
- **能拿來做什麼**：透過多個 AI agent 角色扮演師生互動，模擬沉浸式課堂學習體驗；有 Live Demo、JCST 2026 論文背書，README 提供中英文指南。
- **編輯點評**：學術機構背書加上期刊論文是加分項，代表設計有理論基礎而非純行銷。然而「多 agent 教學」的實際教學成效、課程設計深度，以及與現有 AI tutor 工具（如 Khan Academy AI）的差異，僅從 README 無法確認。TypeScript + Next.js 技術棧對前端工程師友善，但教育場景的留存率問題非程式碼能解決。

### [tashfeenahmed/freellmapi](https://github.com/tashfeenahmed/freellmapi)　⭐ 23,009（今日 +504）
- **一句話定位**：聚合 34 家免費 LLM 供應商、635 個端點，統一在單一 `/v1` OpenAI 相容 API 後面，自動容錯切換。
- **能拿來做什麼**：個人實驗用途，省去管理多組 API key 的麻煩；支援 Docker 自架、桌面 App（macOS/Windows/Android），每月宣稱可用 74 億 token。
- **編輯點評**：「Personal experimentation only」的免責聲明值得注意——各家免費 tier 的 ToS 不一，批量代理可能觸碰灰色地帶。$19/yr 的付費升級版（即時模型目錄更新）顯示這是有商業動機的開源，免費版目錄延遲 30 天接收新模型。作為個人快速試驗工具尚可，用於任何生產環境前需仔細閱讀各供應商條款。

### [p-e-w/heretic](https://github.com/p-e-w/heretic)　⭐ 29,313（今日 +369）
- **一句話定位**：基於 directional ablation（abliteration）技術的全自動 LLM 安全對齊移除工具。
- **能拿來做什麼**：無需重新訓練，透過 Optuna TPE 優化器自動搜尋最佳 abliteration 參數，同時最小化拒絕回應數與對原始模型的 KL 散度；支援多數 dense 模型及部分 MoE 架構。
- **編輯點評**：技術路線清楚引用 Arditi et al. 2024 及後續研究，方法論相對嚴謹。2025 年 9 月創立，近 3 萬星，顯示這個需求確實存在。然而使用此類工具的法律與倫理責任完全由使用者承擔，且移除安全對齊後的模型行為可預測性降低。純 SSM 架構尚不支援。

### [hkqr/my-free-code](https://github.com/hkqr/my-free-code)　⭐ 415
- **一句話定位**：本機 multi-provider gateway，讓 Claude Code 等 coding agent 透過統一端點路由至 40+ 供應商，支援 fallback 與本地模型。
- **能拿來做什麼**：同時支援 Anthropic Messages 與 OpenAI Responses 協議，具備 Claude tier 路由（Opus/Sonnet/Haiku 對應）、ordered fallback、provider health backoff；launcher adapter 覆蓋 Claude Code、Codex、Pi、OpenCode、Cline 等多個 agent。

### [OnlyTerp/opengrok](https://github.com/OnlyTerp/opengrok)　⭐ 384
- **一句話定位**：讓 Grok Bot 能換用其他模型的路由工具，針對各模型家族修正 wire protocol 差異，宣稱每項設定均有封包捕獲佐證。
- **能拿來做什麼**：一行指令設定，圖形化 model picker 選擇每個 agent 使用的模型，`doctor.py` 隨時健檢；重點是針對 GLM、Claude、Gemini、DeepSeek 等各自的 reasoning 參數傳遞方式做了正確對應，避免 harness mismatch。
- **編輯點評**：「evidence-based wire maps，每個 claim 都有 wire-captures 佐證」的訴求在同類工具中罕見，技術誠信度較高。但 Grok Bot 本身的 update 可能隨時破壞 wire mapping，「update-proof doctor」能否真正追上變化仍是未知數。3 天前上線，星數僅 384，屬於極早期。

## 收盤註記

今日清單明顯呈現兩條主線：一是「agent skill 生態系的基礎設施化」——從圖表渲染（archify）、科學計算（scientific-agent-skills）、話題研究（last30days）到寫作修飾（sepia），agent skill 的垂直化分工正在快速發生；二是「AI 工具成本與供應商碎片化的反彈」——tokentab、freellmapi、my-free-code、opengrok 都在試圖解決同一個問題：開發者同時使用多個 LLM 工具卻缺乏統一的成本追蹤與路由層。值得注意的是，今日多個高星數專案仍是 4 月以後才創立，成熟度與聲量的落差需要理性看待。
