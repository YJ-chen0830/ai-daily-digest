## 📌 頭版焦點

### FareedKhan-dev/kimi-k3-in-c：2.78 兆參數模型，8GB RAM，純 C99 跑起來

這個專案只有兩天歷史，卻直接挑戰「大模型一定需要 GPU」的認知框架。作者用不到 176KB 的 C99 程式碼，從零實作 Kimi K3（2.78 兆參數）的推論引擎——無 BLAS、無框架、無 GPU，只靠 AVX2 SIMD 和 MoE 稀疏 expert streaming 的架構特性，把峰值記憶體壓到 8.24GB。

技術立論有其邏輯：Kimi K3 是 MoE 架構，每次推論只啟用部分 expert，因此 dense trunk 可留在記憶體，1.45TB 的 routed experts 則逐需串流、從不全量載入。代價是速度——8GB 模式下每 token 要 32 秒，即便是 128GB server 模式也要 10.69 秒/token。

目前版本 0.1.0，僅支援 Linux x86-64，需要 1.56TB 的磁碟空間放 checkpoint。對多數人而言仍是概念驗證，但它的意義在於：為嵌入式或離線邊緣推論開了一條研究路徑，也順帶示範 MoE 稀疏性在記憶體節省上的實際效益。專案剛起步，文件與 benchmark 資料放在 `docs/data/`，成熟度待觀察。

## 收盤註記

今日榜單可見兩條清晰脈絡：其一，**AI Agent 的記憶、感知與行為約束**三個基礎設施問題正在被同步攻克——TencentDB-Agent-Memory 管記憶、Agent-Reach 管感知、ratchet 管行為規範，說明工具鏈正從「讓 agent 能動」演進至「讓 agent 可控」。其二，**極限記憶體推論**依然是熱點，airllm 與 kimi-k3-in-c 代表兩種路線（Python 易用性 vs. C 極致輕量），背後驅動力是消費級硬體跑大模型的持續需求。值得留意的是，reverse-skill 的星數成長曲線與實際技術深度之間存在明顯落差，在安全工具領域對快速爆紅的專案保持審慎仍有必要。
