## 📌 頭版焦點

### [Sandflow-ai/sand3d](https://github.com/Sandflow-ai/sand3d)　⭐ 1,492

sand3d 是一個以 LLM 為第一用戶設計的 3D 建模 Python 函式庫，底層跑 Blender 的 `bpy`，但把操作抽象成 profiles、solids、joints、assemblies 等高階原語，號稱比直接寫 Blender Python、CadQuery 或 FeatureScript 少用 2–6 倍 token。

這個方向的思路很清晰：現有 3D 工具的 API 是給人設計的，token 冗餘度高；若要讓 LLM 可靠地生成 3D 物件，就需要一套「程式碼即幾何描述」的精簡語言，讓模型只需幾百個 token 就能表達一個零件，人類工程師也看得懂、能 debug。

Sandflow 同時釋出了 Hugging Face 上的訓練資料集與互動式 Explorer，顯示他們在佈局完整的模型訓練閉環，不只是工具本身。對 AI 驅動 CAD、程序式建模、數位製造等賽道的從業者值得持續追蹤。專案建立僅六天即累積近 1,500 星，成長速度快，但成熟度仍待觀察——Apache-2.0 授權，CI 徽章顯示有自動化測試，基本盤尚算扎實。

### [TIGER-AI-Lab/WebsiteBench](https://github.com/TIGER-AI-Lab/WebsiteBench)　⭐ 143
- **一句話定位**：讓 AI Agent 透過瀏覽器探索真實網站，然後嘗試逆向重建出可運作的 full-stack 複製品，以此評估 Agent 的軟體工程能力。
- **能拿來做什麼**：評測 LLM-based 編程 Agent 的網頁開發能力；包含 70 個任務、逾 46,000 筆隱藏測試案例，評分同時考量 SSIM 視覺相似度（≥0.99）與功能正確性。可透過 `pip install websitebench` 下載並以 Harbor 框架執行。
- **編輯點評**：這是繼 SWE-bench 之後，針對「瀏覽器探索→程式碼重建」場景最具體的評測框架。評分標準設計嚴格（SSIM 閾值 0.99 + 功能測試雙重把關），具有一定可信度。不過依賴 Docker + Harbor 環境，本地跑完整 benchmark 的門檻不低；且 70 個網站的覆蓋廣度能否代表真實世界複雜度，仍需社群驗證。

### [reason-machines/aspen](https://github.com/reason-machines/aspen)　⭐ 86
- **一句話定位**：用 Rust 寫的可自架 Git 伺服器，把 pack 存入物件儲存（S3 相容），branch history 存入 PostgreSQL，專為數百個 Agent 並發 push/fetch 設計。
- **能拿來做什麼**：解決傳統 Git 伺服器在大量 Agent 並發寫入時的鎖競爭與 repack 瓶頸；每個 branch 以 CAS（compare-and-swap）獨立更新，不同 branch 的 push 互不等待。設計參考了 OpenAI Pando 與 Cursor Origin 的架構思路。
- **編輯點評**：**Pre-alpha，明確警告儲存格式可能變動，不可存放重要資料。** 但設計方向紮實，有公開的 live demo（像素畫布，每筆筆觸都是一個 `git push`），也有詳細的設計文章。隨著 Agentic CI/CD 需求增長，「Git 伺服器能不能撐住千個 Agent」會是真實痛點，這個專案的出現時機恰當，值得關注後續是否能推出穩定 release。

### [YT-Proteus-bot/MineAgent](https://github.com/YT-Proteus-bot/MineAgent)　⭐ 111
- **一句話定位**：本地運行的 Agent 流程視覺化編排工具，拖拉節點連線後一鍵編譯成可獨立執行的 Python Agent 專案。
- **能拿來做什麼**：在瀏覽器畫布上搭建 LangChain/LangGraph、AutoGen、CrewAI 等框架的 Agent 流程；內建 110 種節點、33 個推理模式模板（ReAct、CoT、Plan-and-Execute 等）；保存時自動生成對應 Python 程式碼，運行時逐 token 串流回顯並高亮當前執行節點。
- **編輯點評**：功能描述相當完整，前後端分離（React 18 + FastAPI + SQLite），啟動方式對 Windows 用戶友善。與 Dify、Flowise 等競品相比，這個專案強調「直接生成可讀的 Python 程式碼」而非鎖在平台內，是值得肯定的設計原則。唯專案屬個人開發、文件主要為簡體中文、未標示版本號，社群支援能力仍需觀察。

### [yucezerey/turkish-anti-ai-skill](https://github.com/yucezerey/turkish-anti-ai-skill)　⭐ 274
- **一句話定位**：針對土耳其語的 AI 文字「去機器味」工具，修復的不只是用詞，而是 LLM 輸出的英語句式架構滲透問題（Translationese）。
- **能拿來做什麼**：作為 Agent Skill 整合進 Claude Code、Cursor、Gemini CLI 等工具；自動偵測並重寫「右分支修飾語」、機械式 `ve` 連詞、`-DIr/-mAktAdIr` 句尾一致性、以及缺乏節奏變化的 18–22 字長句帶等 AI 土耳其語特徵。
- **編輯點評**：這個專案點出了一個跨語言都存在但鮮少被系統性處理的問題——LLM 以英語語法骨架生成其他語言。技術切入點比一般「換個說法」的 humanizer 深，從 README 的前後對比來看效果可辨識。但仍屬小眾語言工具，能否泛化為其他語言的框架，仍有待觀察。

## 收盤註記

今日最值得注意的結構性訊號是兩個方向的交叉：一是「為 LLM 重新設計介面」的專案持續湧現（sand3d 壓縮 3D 建模 token、turkish-anti-ai-skill 修復語言架構、MineAgent 視覺化 Agent 編排），顯示開發者已不滿足於把 LLM 接上現有 API，而是在重塑工具本身的表達層。二是 Agent 並發需求開始倒逼基礎設施（Aspen 的 Git 伺服器改造），這個方向雖然目前星數低、成熟度最低，卻可能是未來幾年 Agentic 系統工程化的關鍵瓶頸。今日也出現數個僅提供封裝二進位、無原始碼可查的「開源」專案，提醒讀者對此類專案的「開源」宣稱保持戒心。
