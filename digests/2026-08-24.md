## 📌 頭版焦點

### mattpocock/skills — AI 時代的工程師 Playbook 正在被集體書寫

[mattpocock/skills](https://github.com/mattpocock/skills) 是 Total TypeScript 作者 Matt Pocock 從個人 `.agents` 目錄整理出來的一套 AI coding agent 技能集，今日新增 2,447 顆星，累計已達 233,970 顆，是本日漲幅第二的專案。

這件事本身沒那麼稀奇，但背後的現象值得注意：這個 repo 從 2026 年 2 月建立至今累積出比許多成熟工具更高的聲量，靠的不是框架或 SDK，而是「給 AI agent 用的提示詞與工作流程規則」——也就是所謂的 agent skill。

它的設計哲學刻意與 GSD、BMAD 等「接管全流程」的方案做出區隔：skills 小、可組合、不搶走工程師的控制權。安裝方式分兩派：透過 Claude Code 官方 plugin marketplace 訂閱（只讀、自動更新），或用 `skills.sh` 複製到本地自行修改。兩者哲學截然不同，前者像訂閱 SaaS，後者像 fork 一個 dotfiles。

更深層的意義在於：這個 repo 的存在說明 prompt engineering 已經從「寫一段文字」演化成「維護一個 skill library」，且這個 library 本身正在成為工程師之間可流通的資產。今日精選中的 ECC、Hermes Agent、book-to-skill 等專案都圍繞相同主題，這不是巧合。

## 收盤註記

今日九個專案中，至少六個與「AI agent 的 skill/memory/trajectory 管理」直接相關，這條脈絡在 2026 年已從邊緣話題演變為主流工程議題。值得留意的是，部分高星數專案（ECC、Hermes Agent）的成長曲線與建立時間不成比例，在缺乏外部佐證的情況下，star 數的參考價值需打折。真正低調但務實的是 only-cli/oc 與 book-to-skill 這類定位明確、解決具體 token 成本問題的小工具——這類工具通常比聲量更大的「全棧 agent 框架」更容易在真實工作流中存活。
